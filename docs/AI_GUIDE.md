# Как добавлять функции в Deep Mine через нейросеть и не тратить кучу токенов

## Главная идея
Не показывайте нейросети весь проект. Покажите **карту проекта** (раздел ниже) и **1–3 нужных файла**.
Проект устроен так, что большинство новых функций — это **один новый файл + одна строка регистрации**.

## Карта проекта (копируйте этот блок в начало запроса)
```
Deep Mine: Three.js (клиент) + Node/Socket.IO (сервер). ES-модули, без сборщика, комментарии на русском.
Сервер авторитетный: клиент шлёт намерения, сервер проверяет и рассылает результат.

shared/            общий код клиента и сервера (чистые функции, без DOM)
  blocks.js        блоки (BLOCK_INFO), предметы (ITEMS), 22 кирки (PICK_TABLE)
  worldgen.js      генерация мира, список блоков BLOCK
  enchants.js      РЕЕСТР ЧАР: ENCHANTS. Новая чара = новый объект. Хуки: stats / extraTargets / dropBonus
  economy.js       состояние игрока {money, items, pickaxes, equipped, enchants}, продажа и покупка
  building.js      что можно строить и правила постановки
server/
  game.js          ядро: join/move/hit/place/shop/chat + API плагинов. Меняется редко
  world.js         мир на сервере (hit — удар по блоку)
  features/        СЕРВЕРНЫЕ ПЛАГИНЫ. index.js — список. trade.js, enchant-shop.js — примеры;
                   persistence.js — логика сохранений (аккаунты, карта)
  storage/         ХРАНИЛИЩА: file-store.js (data/*.json), supabase-store.js (Supabase REST), index.js выбирает по env
client/js/
  main.js          сборка клиента: подключение модулей, клавиши, игровой цикл
  mining.js building.js inventory.js ui.js (HUD и магазин) multiplayer.js (сеть) chat.js touch.js
  features/        КЛИЕНТСКИЕ ПЛАГИНЫ. trade-panel.js — пример (сам создаёт HTML и CSS)
tests/             game.test.mjs, features.test.mjs (запуск: npm test, без браузера)

API серверного плагина: export default function register(api)
  api.onEvent('имя', ({me, socket}, data, reply) => reply({ok:true}))   обработчик события клиента
  api.command('имя', 'описание', ({me}, args, say) => say('текст'))       чат-команда /имя
  api.sendState(player)   api.say(player, текст)   api.findPlayer(ник)
  api.players  api.world  api.io  api.now()  api.log()  api.dataDir (папка сохранений)
  Хуки жизненного цикла: api.beforeJoin(ctx => 'ошибка'|undefined)  api.afterJoin((player, ctx) => …)
                         api.onLeave(player => …)  api.onStop(() => …)
Клиент вызывает плагин так: net.request('имя', data) -> Promise<{ok, error?}>
Состояние игрока (me.state) отправляется клиенту через api.sendState(me).
```

## Что где менять (шпаргалка)
| Хочу добавить… | Что менять |
|---|---|
| Новую **чару** (например «Жила», «Магнит») | Только `shared/enchants.js`: новый объект в `ENCHANTS`. Магазин и сервер подхватят сами |
| Новую **чат-команду** | Новый файл в `server/features/` + строка в `features/index.js` |
| **Серверную** механику (обмен, банк, квесты) | Файл в `server/features/` + строка в `index.js` |
| **Окно/кнопку** на клиенте | Файл в `client/js/features/` + 1 строка в `main.js` (по образцу `trade-panel.js`) |
| Новую **руду / предмет** | `blocks.js` (BLOCK_INFO, ITEMS), `worldgen.js` (BLOCK и размещение), `atlas.js` (текстура) |
| Новую **кирку** | Одна строка в `PICK_TABLE` в `shared/blocks.js` |
| Сохранять **новые поля** игрока | `sanitizeState` и `snapshot` в `server/features/persistence.js` + значение по умолчанию в `createPlayerState` |
| Перейти на **другую базу** (SQLite, Postgres…) | Новый файл в `server/storage/` с методами `loadAccounts/saveAccounts/loadWorld/saveWorld` + строка в `storage/index.js`. Образец: `supabase-store.js` |
| Новый **хук для чар** (например «при ломании блока») | `shared/enchants.js` (хелпер) + 1 вызов в `hit` в `server/game.js` |

## Рецепт 1. Новая чара (самое дешёвое)
Откройте `shared/enchants.js` и допишите объект. Пример — чара «Скорость ходьбы» не нужна, но вот шаблон:
```js
magnet: {
  id: 'magnet', name: 'Магнит', icon: '🧲',
  desc: 'Шанс +1 уголь/медь…',
  costs: [1000, 3000],                 // цена каждого уровня; длина = макс. уровень
  dropBonus: (level, rng) => (rng() < 0.1 * level ? 1 : 0),
},
```
Больше ничего менять не надо: кнопка в мастерской, покупка, проверка на сервере — работают автоматически.
Если нужна механика, которой нет среди хуков `stats / extraTargets / dropBonus` — просите нейросеть **добавить новый хук**
(его место — функция-помощник в `enchants.js` и один вызов в обработчике `hit` в `server/game.js`).

## Рецепт 2. Новая серверная функция (плагин)
1. Создать `server/features/имя.js` с `export default function register(api) { ... }`.
2. Добавить в `server/features/index.js`: `import имя from './имя.js'` и в массив `features`.
3. Написать тест в `tests/` по образцу `features.test.mjs` и запустить `npm test`.

## Рецепт 3. Новое окно на клиенте
1. Создать `client/js/features/имя.js` по образцу `trade-panel.js`: класс сам создаёт свои HTML/CSS и ходит на сервер через `net.request`.
2. В `main.js` одна строка `new Имя({ net, inventory, ... })` рядом с `TradePanel`.
3. Если окно открывается клавишей — добавить `trade.isOpen`-подобную проверку в обработчики клавиш/Pointer Lock (смотрите, как сделано для `trade`).

## Правила экономии токенов
1. **Один запрос — одна функция.** Не просите «добавь клан, банк и квесты» сразу.
2. **Даёте: карту + нужные файлы.** Обычно хватает 1–3 файлов. Весь проект — почти никогда.
3. **Просите менять «только указанные файлы»** и выдавать **изменения (diff / заменяемые куски)**, а не файлы целиком.
4. **Новая функция — в отдельный файл**, а не в `main.js` или `game.js` (они большие).
5. **Просите тест** для серверной части — это ловит ошибки без запуска игры.
6. Состояние игрока хранится в `me.state`; при добавлении новых полей — задавайте значение по умолчанию в `shared/economy.js` (`createPlayerState`).
7. **Сервер — источник правды.** Всё, что влияет на баланс (деньги, предметы, урон), проверяйте на сервере.

## Шаблон запроса
```
[вставьте «Карту проекта»]

Задача: <одной фразой, что должно получиться и как выглядит для игрока>.
Файлы для изменения: <список>. Новые файлы допустимы только в server/features/ и client/js/features/.
Прикладываю: <содержимое 1–3 нужных файлов>.
Требования: не менять остальной код; выдать только изменённые куски с указанием файла; добавить тест в tests/; все проверки на сервере.
```

## Примеры готовых запросов
**1. Новая чара «Жила» (ломает всю связанную жилу руды)**
> Задача: чара «Жила» — удар по руде ломает до 8 соседних блоков той же руды. Файл: `shared/enchants.js` (хук `extraTargets`; для поиска соседей нужен доступ к миру — предложи, как лучше передать `getBlock` в хук, и измени вызов в `hit` в `server/game.js`). Прикладываю: `shared/enchants.js` и блок `hit` из `server/game.js`.

**2. Команда `/pay` + журнал передач**
> Задача: команда `/log` показывает игроку последние 10 его передач из `trade`. Только `server/features/trade.js`. Прикладываю его. Добавь тест.

**3. Новая руда «Мифрилит»**
> Задача: руда «Мифрилит» на глубине y<8, нужна кирка №16, цена 600. Файлы: `shared/blocks.js`, `shared/worldgen.js`, `client/js/atlas.js`. Прикладываю нужные места. Текстура — фиолетовые вкрапления.

**4. Окно «Квесты»**
> Задача: клиентский плагин — окно квестов (кнопка 📜, клавиша Q) и серверный плагин `quests.js`: «добудь 20 железа» → награда 300 монет. Образцы: `client/js/features/trade-panel.js`, `server/features/trade.js`. Файлы только в features/ плюс по одной строке в `index.js` и `main.js`.

**5. Исправление ошибки**
> Ошибка в консоли браузера: `<текст ошибки>`. Файл: `<файл>` (прикладываю). Найди причину и дай минимальное исправление.
